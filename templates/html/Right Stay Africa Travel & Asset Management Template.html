Objectives

  • Showcase curated Airbnb stays with live availability links and deep links to book.
  • Allow visitors to book destination tours directly (outsource fulfillment to partners).
  • Present asset management services for high‑end cars and homes with request intake.
  • Pair guests with tours using smart “Stay + Tour” bundles.
  • Provide an internal dashboard to control homepage content, featured items, and site settings.

Success Criteria

  • Time to first booking under 2 minutes from landing.
  • Admin can update homepage in under 5 minutes, no code.
  • Tour partners can accept bookings via email and partner portal (Phase 2).

Information Architecture

Public

  • Home (Hero, Featured Stays, Top Destinations, Bundles, Asset Mgmt CTA)
  • Stays (search, filters, deep link to Airbnb)
  • Tours (search, bookable, vendor info)
  • Bundles (Stay + Tour suggested packages)
  • Asset Management (services, tiers, intake form)
  • About, Contact, FAQs, Policies

Booking Flow

  • Tour Details → Date/Guests → Checkout → Confirmation
  • Stay Details → “Book on Airbnb” deep link
  • Bundle → Select dates → Split checkout (tour) + external link (stay)

Dashboard

  • Overview (metrics)
  • Content: Homepage blocks, Featured items
  • Stays: curated list, tags, badges
  • Tours: products, inventory, blackout dates
  • Bookings: tours, invoices, statuses
  • Partners: vendors, revenue share
  • Assets: clients, vehicles/homes, service requests
  • Settings: branding, SEO, policies, feature flags
  • Users & Roles

Stays (Airbnb)

  1. 1. Curate listings with images, amenities, and regions.
  2. 2. Show price band, rating, and availability badge.
  3. 3. Deep link to Airbnb “Check Availability/Book”.

Note: If hosts share iCal, ingest to show basic calendar blocks; otherwise display high‑level availability and rely on deep links.

Tours (Direct)

  1. 1. Display tour cards with date options and per‑guest pricing.
  2. 2. Checkout collects customer info and payment.
  3. 3. Auto email confirmation to guest and partner vendor.

Asset Management

  1. 1. Service overview with tiers (Car, Home; Yachts later).
  2. 2. Intake form: identity + asset details + desired dates.
  3. 3. Internal workflow creates service request tickets.

Data Model

Identity

  • profiles (id, name, email, phone, role, avatar_url)
  • roles (id, key: admin/editor/partner/customer)
  • sessions (Supabase Auth)
RLS: users can read own profile; admins full access.

Stays

  • listings (id, title, region, city, hero_img, gallery[], tags[], rating, price_band, airbnb_url, ical_url?, featured:boolean, status)
  • listing_amenities (id, listing_id, key, label)
  • listing_availability (date, listing_id, status) [optional from iCal]

Tours

  • tours (id, title, slug, location, hero_img, gallery[], summary, inclusions[], exclusions[], duration, rating, featured, vendor_id)
  • tour_options (id, tour_id, date, price, capacity, seats_left, currency)
  • tour_bookings (id, tour_id, option_id, user_id, guests, total, status, payment_ref, notes)
  • vendors (id, name, email, phone, revenue_share, payout_details)

Bundles

  • bundles (id, title, listing_id, tour_id, desc, recommended_days, featured)

Assets

  • asset_clients (id, profile_id, tier, notes)
  • assets (id, client_id, type:car|home, title, make_model?, address?, images[], status)
  • service_requests (id, asset_id, request_type, desired_date, status, cost_estimate, assigned_to, notes)

CMS & Settings

  • content_blocks (id, key, title, body_rich, media[], order, visible)
  • site_settings (id, brand, logo_url, theme, seo, contact)
  • feature_flags (key, enabled)

  • Supabase for auth, RLS, storage, SQL migrations, edge functions (iCal ingest).
  • Image optimization and metadata for SEO + social cards.

Security & Policies

  • Auth: Email OTP + Social; enforce email verification.
  • RLS examples:
    • profiles: user_id = auth.uid()
    • tour_bookings: user can read own; admin/partner by vendor_id
    • content_blocks/site_settings: read all; write admin/editor
  • Webhooks: payment success → mark booking paid → email guest & vendor.
  • Storage: signed URLs for media, role‑gated uploads.

Implementation Steps

  1. Week 1 — Setup
    • Init Next.js app, configure Supabase client and auth.
    • Create DB tables and RLS policies; seed content.
    • Base layout, typography, color tokens.
  2. Week 2 — Marketing pages
    • Home, Stays index + detail, Tours index + detail.
    • Asset Mgmt page + intake form (stores service_requests).
  3. Week 3 — Checkout & Bookings
    • Tour checkout flow, payments, success page.
    • Webhooks to confirm bookings and notify vendors.
  4. Week 4 — Dashboard
    • Role‑based access, overview metrics.
    • Content manager for homepage blocks, featured items.
  5. Week 5 — Bundles & iCal
    • Bundle creation + presentation on home/bundles page.
    • Edge function to parse iCal (if provided) → listing_availability.
  6. Week 6 — QA & Launch
    • SEO, performance, analytics, error tracking.
    • Partner onboarding and content polish.
