A comprehensive architectural and design specification for a high-performance, real-time financial data platform. Focus on zero-surprise UX, data density without clutter, and extreme performance.

Product Philosophy

LAW 01

Zero Surprise Architecture

Every interaction should feel known. No tooltips required for core flows. No "where did that go?" moments.

LAW 02

Data Density ≠ Clutter

Organize dashboards around what a user is trying to decide, not just what data is available in the API.

LAW 03

Performance is a Feature

An 80ms chart load vs 400ms is a UX differentiator. Architecture choices prioritize rendering speed.

Data Pipeline Contract

Any external API (CoinGecko, Binance) must be transformed to an internal schema in the proxy layer. This decouples the UI from external provider changes.

types/market.ts 
type NormalizedAsset = {
  id: string;           // coingecko slug
  symbol: string;       // uppercase ticker
  name: string;
  price: {
    usd: number;
    btc: number;
    change_24h: number;
  };
  volume_24h_usd: number;
  last_updated: string; // ISO timestamp
};

Three-Tier Freshness Model

Tier 1: Static 3-24h
Asset metadata, sector definitions. SSG with on-demand revalidation.
Tier 2: Warm Cache 60-180s
OHLC candles, volumes. Server-side RSC with revalidate intervals.
Tier 3: Live Edge < 5s
Order books, prices. SSE (Server-Sent Events) preferred over raw WebSockets.
