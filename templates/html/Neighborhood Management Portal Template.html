Recommended architecture

  • App: Next.js (app router) with SSR/ISR
  • Auth: OAuth/email + session/JWT; per-tenant RBAC
  • Data: Postgres with Row-Level Security (tenant_id)
  • API: tRPC/REST; input validation (zod)
  • Storage: S3-compatible buckets (scoped by tenant)
  • Secrets: Managed KMS; per-tenant encryption contexts

Security validation: Enforce tenant_id in token claims and RLS policies; never trust client-sent tenant_id. All queries scoped server-side. Secrets isolated. ✅

FAQ

How do you isolate tenant data?

By enforcing tenant_id at the database layer with RLS and scoping all queries server-side. Tokens include tenant claims and roles.

Can I migrate documents from another system?

Yes. We provide import tooling and map documents into tenant-scoped storage with preserved metadata.

Do you support SSO?

SAML and OIDC are supported for enterprise tenants.
